# M7: NRC と Adaptive Integrator

目標: 間接光をニューラルキャッシュ（NRC）で近似し、学習と推論の時間を含めて同画質到達時間が縮むかを実測する。縮まなければ無効のまま、その結果を記録して終える。そのうえで、領域ごとに Physical PT・ReSTIR・NRC を選ぶ Adaptive Integrator が、単独の方式より良いかを調べる。
依存: M1〜M6（特に M5 の ReSTIR と差分更新、M3 の Wavefront、M4 の Vulkan、M6 の Blender 連携）。方針: ADR-0001 / 0011 / 0016 / 0017。要件: REQ-ACC-004（NRC）、REQ-ACC-006（Adaptive Integrator、研究）。

M7 は研究の段階で、結果が「効かない」でも成果になる。そのため順序は「測る土台 → 方式の決定 → 最小の実装 → 信頼度とフォールバック → 評価（続けるかの判断）→ Vulkan → Adaptive Integrator」とし、評価の前に統合や UI へ進まない。

## M7 の前に入れるもの: 画像のアルファによる切り抜き

M6 の積み残し（2026-11-06 に利用者が M7 の前に入れると決めた）。M7 は Buffer とシェーダーを増やすので、材質のレイアウトを変える作業を先に済ませる。いまは glTF も Blender も画像のアルファを読まず、Blender では警告して不透明にしている（葉・フェンス・髪の板などが塗りつぶされる）。

## 決めてあること

- NRC は選択式で既定は無効。Reference モードは必ず通らない（REQ-CORE-006）。バイアスを持つので、有効なら出力に非物理の印を付ける
- 測ってから続ける。8 の評価で学習込みの利益が出なければ、9 以降を行わず、無効のまま結果を記録する（REQ-ACC-004 の「無効化」）。小さなシーンでは効かない可能性が高いので、評価シーンの選び方を 1 で先に固める
- ネットワークの実行は Slang の自前カーネルを先にする（2026-11-06 に利用者が決定）。Metal と Vulkan で同じソースにでき、依存が増えない。Render Graph（REQ-GPU-008）は、CUDA を足すときに外部セマフォの同期が要るので、その時点まで入れない
- キャッシュに入れるのは物理の Radiance で、Stylization は後段のまま（REQ-ACC-004）。Stylization は Lighting AOV（Direct Diffuse・Indirect Diffuse・Specular・Shadow など）を入力にするので、NRC はまず間接の拡散だけを置き換え、成分の分離を壊さない。鏡面とコースティクスは物理 PT のまま
- 履歴は編集で捨てるという ADR-0017 の方針は、NRC では「捨てる」か「継続学習で追従する」を 6 で測って決める。それまでは、編集があったら信頼度を下げて物理 PT に戻す
- Slang で一度書き、Metal を先にする（ADR-0001、ADR-0002）。CUDA の経路は NVIDIA 機での作業を待つ
- 新しい依存は都度確認する。商用再配布できるものだけで、`mise run deny` を通す
- 画素単位の Adaptive Sampling（ADR-0015）は、サンプルをどの画素に割くかを決める。Adaptive Integrator は、どの方式で描くかを決める。別の仕組みとして並べる
- NRC を MORT の制御変量 L0 にして不偏にする案は採らない（2026-11-07 に Metal の GPU で測定。`experiments/mort-spike` ブランチ、`mort_spike` example）。Oracle の L0（グリッド上の入射放射輝度。SH L2 と八面体 8×8）で、同じ GPU 時間あたりの効率が plain の 0.25〜0.69 倍（球あり）、0.42 倍（拡散のみ。分散は 18% しか下がらず、コストは約 3 倍）だった。ArcheRender の MORT の S1 基準（4 倍以上）に届かない。不偏性は確認できた（平均の比 1.000 前後）。NRC は、偏りを許して非物理の印を付ける形で進める
- 8 の評価の上限の目安: 1 次ヒットで経路を切り、`Le + NEE + L0` だけで描く偏りのある版は、拡散のみの Cornell で plain の約 6 倍の効率だった（Oracle の L0、焼き込み 4.5 s は含めない。L0 の偏りは約 1%）。学習込みの NRC がこの値にどこまで近づくかを、8 で見る。1 seed の結果なので、目安として扱う

## 要確認（利用者）

- 8 の続けるかの基準の数値（同画質到達時間で何倍以上か）。最初の測定を見てから決める（REQ-PERF-003 のように仮置きにして見直す）
- 10 の ReSTIR PT の結果の反映（REQ-ACC-002 の書き換え）
- REQ-ACC-006 は優先度 Could の研究。11 と 12 を M7 に含めるか、NRC の評価が終わってから決めるか
- M1/M2 チップ（RT 非搭載）の扱い（13）
- Octane との同画質到達時間の比較（M5 から持ち越し。REQ-ACC-002）。NRC の評価と同じシーンで行うと条件が揃う
- DELTA（連番の差分推定とフル再計算の結合。ArcheRender の機能化トラック）は M7 の対象外。Verion に連番の仕組みと差分推定器が要るので、ArcheRender の CPU 実験（S1）が基準を通ってから、別のマイルストーンとして計画する
