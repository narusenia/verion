# ADR-0016: ReSTIR は DI と GI を Interactive モードに入れ、PT は M7 の後に判断する

- 状態: 採用
- 日付: 2026-11-06

## 背景

M5 の目的は、同画質に届く時間を縮めること（REQ-ACC-002）。要件は DI → GI → PT の順で、鏡面・屈折・Motion Blur・DoF では Fallback、Reference では通らない。

## 決定

- **DI**: 最初のヒットの Emitter 三角形の光サンプルを、画素ごとの Reservoir から選ぶ。初期候補（既定 4）を Emitter の放射量で引き、前フレームの同じ画素と近傍 2 画素の Reservoir を重ねる。勝った 1 サンプルだけ影を調べ、隠れた勝者は重み 0 で保存して影を広げない。環境マップは Reservoir に入れず、常に通常の光サンプリングで引く
- **MIS は残す**。BSDF サンプルが Emitter に当たる寄与は、光サンプリングの密度（初期候補の密度）との Power Heuristic で重みを付ける。重みはサンプル位置だけで決まる関数なので、Reservoir で選ばれたサンプルにもそのまま掛けられる。MIS を外した最初の版は、天井の近くの小さなパネルで 1/d² の外れ値が出て、通常より悪かった
- **GI**: 最初のバウンスが当たった面の点と法線、そこから先の経路が集めた放射輝度を Reservoir に入れる。前フレームの近傍のサンプルは、点と放射輝度をそのままに新しい光線へつなぎ替え、立体角の変化（Jacobian、0.1〜10 の範囲だけ採る）で重みを直す。つなぎ替えた光線の可視性は 1 本ずつ調べる。自分の経路の候補は経路の終わりに足して 1 つ選ぶ。経路が 1 回目のバウンスで空へ抜けた画素は、空の寄与をそのまま使う
- **GI から外すもの**: 深さ 1 の BSDF サンプルが Emitter に当たる寄与。重みが元の画素の視点で決まるので、別の画素へ再利用すると DI と二重に数える。これを GI に入れた最初の版は PSNR が 40 dB で頭打ちになった（外すと 45〜49 dB）
- **対象の面**: 粗さ（alpha）が 0.15 以上で、透過がなく、コートが鋭くなく、レンズのぼけがない面だけ。それ以外は従来の光サンプリングと BSDF の MIS（画素ごとに Fallback）。GI は Lighting AOV の分離と両立しないので、Stylized では DI だけが動く
- **GI から外すもの（ガラス）**: 反射先（2 番目の面）が透過する面の経路と、分散で 1 色を選んだ経路は、再利用に出さず自分の画素の分だけに使う。ガラスでは出ていく方向が入ってくる方向で決まるのでつなぎ替えが成り立たず、分散の経路は 1 色を 3 倍した光を持つので、借りた画素と次のフレームに色のシミを残す。Cornell Box のガラスを ior 2.4・dispersion 20 にしたとき、壁の 8×8 ブロック平均の最大差が 0.50、赤青のバランスの最大差が 0.26 だったものが、0.18 と 0.08 になった（通常の経路は 0.15 と 0.04。テスト `gi_leaves_no_stains_on_the_cornell_box_walls`）
- **履歴の上限（既定 4）**: 再利用した Reservoir が数えられる最大のサンプル数。大きいほど長く再利用するが、フレーム間の相関が残り、蓄積しても誤差が下がり切らない（上限 20 で PSNR が 31 dB で止まったシーンが、2〜4 では 35〜39 dB まで下がった）
- **Interactive モード**: `render-cli --mode interactive`（REQ-CORE-007）。ReSTIR DI と GI が既定で有効、Stylization Pass なし、非物理。`--restir`（DI）、`--restir-gi[=false]`、`--restir-candidates`、`--restir-history` で調整する。Reference と組み合わせるとエラーにする
- **出力**: 非物理。EXR に `verion/physical = false` と `verion/restir = di | di+gi`
- 履歴は編集で捨てる（ADR-0017）。蓄積が 0 から始まるたびに Reservoir も空になる
- 両方の積分器で同じコードを使い、画像がビット一致する（テスト）。Megakernel は ReSTIR が有効なときだけ 1 Dispatch 1 サンプルにする（他画素の前フレームを読むため）

## 測定

Apple M4 Pro、512×384、参照 4096 spp、基準は Reference の 128 spp の誤差（`exr_diff` の mae/mean）。各構成がその誤差に届くまでの GPU 時間（対数補間、`scripts/eval_restir.sh`。GPU の時間は実行ごとに 2 割ほど揺れる）:

| シーン | Reference s | DI のみ | DI + GI |
|---|---|---|---|
| many_lights（256 枚のパネル、間接光が支配的） | 0.903 | 0.932 秒（0.97 倍） | 0.184 秒（4.90 倍） |
| many_lights_dark（壁が暗く直接光が支配的） | 0.415 | 0.225 秒（1.84 倍） | 0.222 秒（1.87 倍） |
| cornell_box（光源 1 枚） | 0.610 | 0.822 秒（0.74 倍） | 0.210 秒（2.91 倍） |
| showcase（HDRI だけ） | 0.388 | 0.411 秒（0.94 倍） | 0.436 秒（0.89 倍） |

- DI は Emitter が多く、直接光が支配的なときだけ効く。光源が 1 枚の Cornell Box や、Emitter のないシーンでは 1 サンプルあたり 1 割ほど遅くなるだけ
- GI は間接光が支配的な室内で 3〜5 倍。Emitter のないシーンでは効かず、費用だけが乗る
- 1 サンプルあたりの GPU 時間は DI で +10〜25%、GI を足すと +35〜60%
- 高 spp では偏りと相関の下限が見える（1024 spp の PSNR: cornell_box は 47.7 dB で通常は 58.0 dB、many_lights は 38.0 dB で通常は 39.1 dB）。ReSTIR は低 spp で素早くきれいな絵を出すための機能で、最終品質は Reference で出す
- メモリは 1 画素 320 B（Reservoir 2 フレームと作業領域）。1024×768 で 252 MB

NVIDIA GeForce RTX 3080（Vulkan）、512×384、参照 16384 spp（`scripts/eval_restir.sh` の既定。Metal の表は 4096 spp）、同じ基準。Windows 機での測定で、GPU の時間は 1 桁ミリ秒の差になるため、Metal の表より揺れが大きい:

| シーン | Reference s | DI のみ | DI + GI |
|---|---|---|---|
| many_lights | 0.053 | 0.074 秒（0.72 倍） | 0.021 秒（2.58 倍） |
| many_lights_dark | 0.032 | 0.025 秒（1.27 倍） | 0.030 秒（1.04 倍） |
| cornell_box | 0.047 | 0.071 秒（0.66 倍） | 0.030 秒（1.58 倍） |
| showcase | 0.036 | 0.044 秒（0.81 倍） | 0.060 秒（0.59 倍） |

- 傾向は Metal と同じ（DI は直接光が支配的なシーンだけ、GI は間接光が支配的な室内だけ効き、Emitter のないシーンでは費用だけが乗る）。GI の倍率は Metal より小さい（many_lights で 4.90 倍に対し 2.58 倍）。理由は調べていない

## ReSTIR PT について

M5 では入れない。理由は、判断に必要な測定がまだ揃っていないことと、先に決めると後で作り直しになることにある（実装の大きさは理由にしない）:

- PT の効果は、経路全体のシフト写像（再接続の条件、Jacobian）の選び方で決まる。この選び方は M7 の NRC（間接光のキャッシュ）が受け持つ範囲と重なり、どちらが間接光を担うかで最適な形が変わる。ADR-0011 は「ReSTIR の後に NRC を Metal / CUDA の両方を見て判断する」としている。NRC の測定の前に PT の形を固めると、NRC を入れたときに作り直す可能性が高い
- GI の測定で、再利用の効果は間接光が支配的なシーンに限られ、フレーム間の相関による誤差の下限があることが分かった。PT はその相関が経路全体に及ぶので、下限を許せるかは動画（Temporal 再利用、M8）で見ないと評価できない
- PT の効果が最も大きいのは動画で、M8 の範囲

そのため PT は M7 の NRC の測定と並べて、必要かを決める。M5 の時点で PT に先に手を付けたほうが将来的に得だという根拠は見つからなかった。この判断は利用者の確認を待つ（REQ-ACC-002 の書き換えを伴う）。

2026-11-07 の更新: M7 の NRC の測定（ADR-0022）では NRC が ReSTIR GI に勝てず、間接光をどちらが担うかは決まらなかった。PT の効果が最も大きいのは動画なので、判断は M8（Temporal 再利用）に移す。利用者が確認した。


## 結果

- Viewer に ReSTIR DI / GI のスイッチを足した（既定は無効）
- Vulkan への移植は Windows 機で行う。同じ Slang（`pt_core.slang`）を使い、ホスト側はバインディング 19（`restir`）の追加と、`PARAM_WORDS`（39 語）、`Restir` 設定、`restir_bytes` が要る。引き継ぎは `docs/handoff/2026-11-06-m5-windows.md`
